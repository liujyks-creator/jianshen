E16-3 心率 UI 高保真视觉规划

目标不是上线心率功能，而是验证未来如果用户显式启用心率，训练执行页应该如何轻量表达连接和读数状态。所有方案都基于 TrainFlow 现有深色执行页、固定底部主动作和 E15 力量训练最终层级。

推荐方向: Variant A 顶部状态 pill。它在 strength active/rest/confirm-record 和 timed TimerDial 中都不新增大卡片，不挤压确认记录，不改变底部按钮，不恢复旧的心率卡片或未获取心率占位。

默认纯净未启用或训练页没有入口时，不展示任何心率 UI。
辅助状态心率只说明设备来源和数据新鲜度，不做医疗告警、强度建议或训练中断。
实现拆分HTML 方案后仍需单独 Android UI、opt-in、权限说明、隐私文案和 stale 策略 story。
Placement variant
Heart-rate state

Variant A: 顶部状态 pill

把心率放在标题行右侧，作为 session status 的同级辅助状态。它最像现有状态 pill，不产生新卡片，不改 TimerDial，也不干扰力量确认本组。

默认纯净状态

  • 训练页不展示心率入口、不显示未获取心率占位。
  • 主任务保持当前动作、主时间、组目标和固定底部操作。
  • 这是当前 MVP 的默认视觉基线。
