## 1. 权威边界

本合同受 `AGENTS.md`、D-079、D-080、`docs/planning/e17-heart-rate-correct-course.md` 与 `docs/testing/e17-1-band9-hrs-revalidation.md` 约束。E16 原始代码和文档继续是 `sealed historical archive / reference only`，不能自动成为 E17 产品或 runtime 合同。

心率胶囊视觉与互动继续为 `adopted / frozen / direct reuse`。E17-2 只重新定义用户价值、启用、权限、显示时机、设备选择、恢复、状态语义、记录、隐私和后续分析范围，不重新设计胶囊，不设计 BLE / GATT 架构，不修改 production 或测试代码。

## 2. E17-1 事实输入

- 当前真机环境为 `PLU110`、Android 16 / SDK 36 与 HUAWEI Band 9。
- Band 开启心率广播后，四个周期均暴露标准 BLE HRS `0x180D`，并完成 GATT、notify 型 `0x2A37`、`0x2902`、CCCD `01 00` 与连续 notify。
- 广播关闭时，当前扫描窗口没有发现标准 HRS source。
- 开启广播会使 Huawei Health 断开；关闭广播后可恢复。
- TrainFlow 不能替用户开启 Band 心率广播。
- 两次 `status=19` 说明当前链路不能描述为稳定。
- 四周期相同的 label / address 只属于本次观察，不是永久设备身份。
- 该证据不证明 production provider、lifecycle、reconnect、自动恢复或其他环境通用性正确。

## 3. 产品目标与用户价值

- 心率功能默认关闭，不影响 TrainFlow 原有训练闭环。
- 用户主动开启后，心率是训练功能的重要组成，而不是实验或 debug 信息。
- 训练中帮助用户理解当前 bpm、非医疗训练强度区间，以及相对于用户设定上限的高低。
- 训练后通过可信的时间序列、区间分布和统计数据复盘本次训练强度。
- 心率只表达训练反馈，不表示身体安全、疾病风险或医疗结论。

## 4. 默认状态、启用与关闭

- Canonical 入口为 `设置 -> 训练偏好 -> 心率与设备`。
- 默认关闭；App 启动、训练开始和打开记录页均不自动启用。
- 用户开启后，设置页引导其在 Band 9 上手动开启心率广播。
- 关闭心率功能后，胶囊隐藏并停止新的扫描、连接和心率采集；训练中关闭会停止产生新样本，已有区间不补造数据。
- 关闭功能默认保留 saved device 提示和既有训练历史；用户可分别清除设备偏好或删除训练记录。

## 5. 权限、Band 准备与 Huawei Health

- 仅当用户主动点击扫描、连接或“连接已保存设备”时请求必要权限。
- 开启心率开关、App 首次启动和训练自动开始都不触发系统权限请求。
- 用户拒绝权限后，核心训练继续可用；心率区域解释需要权限并等待用户再次主动操作。
- 设置说明必须明确：Band 9 需由用户手动开启心率广播；当前证据中开启广播会使 Huawei Health 暂时断开，关闭广播后可恢复；广播关闭时 TrainFlow 可能找不到标准心率来源。
- Huawei Health 互斥说明只在心率设置与设备准备说明中展示，不在每次连接前重复弹窗。

## 6. 扫描、选择与 saved device

- 扫描和连接始终由用户主动发起，并使用有限时设备查找。
- 用户从发现的兼容心率设备中选择目标。
- TrainFlow 可保存设备显示名称和 identifier，作为下次连接的便利提示；saved device 不表示设备在线、可用或已连接。
- 用户点击“连接已保存设备”后，执行一次有限时精确 identifier 匹配。匹配成功后尝试连接；未匹配时显示“未找到已保存设备”，并允许用户重新扫描和手动选择。
- 名称和 identifier 不得描述为永久设备身份；App 启动时不自动使用 saved device 扫描或连接。
- 当前验证目标是 Band 9 标准心率广播，不承诺所有品牌或设备均兼容。

## 7. 连接、恢复与前后台范围

### 7.1 初始恢复基线

- 断开后显示明确事实状态，由用户手动点击重新连接。
- 手动恢复可使用“连接已保存设备”或重新扫描选择设备。
- 不把上一次 bpm 继续显示为当前实时数据。

### 7.2 前后台产品边界

- 用户开启心率后，TrainFlow 在前台跨页面维持心率显示。
- 活跃训练期间允许锁屏或临时进入后台维持当前心率连接。
- 活跃训练在后台发生断连时，产品目标是自动尝试恢复，避免普通锁屏或切换 App 造成大面积记录缺口。
- 非训练状态进入后台后，不维持连接、持续采集或自动恢复。
- 具体后台持续方式、自动恢复对象、停止条件、用户控制、系统限制和时长不在 E17-2 决定。

### 7.3 自动恢复 Disposition

用户已确认“TrainFlow 前台持续自动恢复”和“活跃训练后台断连自动恢复”具有产品价值。E17-2 将其记录为：

```text
accepted product value / deferred implementation /
requires separate product decision refinement and Story
```

- 初始 production 范围仍以明确状态和手动恢复为可交付基线。
- 自动恢复不在 E17-2 实现，也不是 E17-3 或 E17-4 的默认前置。
- 后续必须独立决定是否自动扫描、是否只恢复当前设备、重试范围、停止条件、用户控制和验收方式。
- 不恢复 E16 D-078 为当前合同，不移植 E16-10b-2 失败 controller 路线，也不把自动恢复与 freshness、provider 或 GATT 架构默认绑定。

## 8. 胶囊显示时机与信息边界

- 心率开关开启后，胶囊可在 TrainFlow 前台跨页面显示。
- 未训练时可以显示实时 bpm、区间和连接状态，但不产生训练记录。
- 训练中胶囊保持辅助层级，不抢占当前动作、时间、重量、次数、TimerDial 或固定主操作。
- 胶囊视觉、布局、collapsed / expanded、拖动、movement threshold、左右吸附、viewport clamp、安全区、IME 收缩与相关动画继续直接复用，不做变体或重新视觉审查。

## 9. 用户可见状态与含义

| 用户文案 | 用户可理解的含义 |
|---|---|
| `心率已关闭` | 用户尚未启用心率功能；胶囊隐藏。 |
| `需要蓝牙权限` | 用户需主动授权后才能查找或连接设备。 |
| `蓝牙已关闭` | 当前无法查找或连接设备。 |
| `未连接` | 当前没有可提供实时数据的设备连接。 |
| `已保存：设备名` | 只保存了下次连接提示，不表示当前在线。 |
| `正在查找设备` | 正在执行用户主动发起的有限时查找。 |
| `未找到已保存设备` | 本次没有找到与 saved identifier 匹配的设备。 |
| `正在连接` | 正在尝试连接用户选择的设备。 |
| `已连接，等待心率` | 设备已连接，但尚无可显示的当前读数。 |
| `区间 · N bpm` | 当前读数有效，并按用户参数显示非医疗强度区间。 |
| `超过设定上限 · N bpm` | 当前值超过用户设置的视觉提示阈值，不是医疗告警。 |
| `数据已中断` | 最近读数不能再当作当前实时数据。 |
| `连接已断开` | 设备连接已经结束，需要恢复。 |
| `连接未成功` | 本次连接尝试没有成功，可由用户重试。 |

E17-2 不规定技术状态机、超时时间、错误码、状态优先级、freshness timer 或 retry timer。

## 10. bpm、区间和上限提示

- 初始实时展示包含 bpm、非医疗强度区间和用户上限视觉提示。
- 区间可表达低强度、热身、燃脂、有氧、无氧、极限和超过设定上限。
- 区间必须基于有效用户参数；年龄、最大心率或必要参数缺失时仍可显示 bpm 和连接状态，但不推导或伪造区间。
- 超过设定上限只使用已冻结胶囊支持的视觉提示，不触发医疗告警、危险警报、声音、震动、强制暂停或训练中断。
- “强度高 / 低”只表示相对于用户区间的训练强度，不表示身体是否安全。

## 11. 记录与分析边界

### 11.1 已接受的后续产品方向

心率记录、历史统计和分析是已确认需要的后续能力，但不在 E17-2 实现。未来只在用户实际开始训练后记录，覆盖运动、休息、暂停和组记录确认等 session 内区间，直到完成或放弃；未训练只显示不记录。

断连期间必须保留为真实数据缺口，不插值、不补造。训练记录必须展示心率数据覆盖情况，避免把不完整数据解释为完整训练。

未来单次训练详情优先支持：

- 平均心率与最高心率。
- 心率时间序列曲线。
- 各心率区间停留时长和占比。
- 数据覆盖范围与缺口说明。
- 克制、非医疗的训练强度说明。

跨训练趋势、训练压力、健康收益、恢复时间、热量修正和其他推断性分析不自动进入初始范围，必须另行验证产品价值、数据质量和非医疗边界。

## 12. 本地隐私、保留与用户导出

- 心率数据默认只在本地处理，不自动上传、不做账号同步、不用于广告或远端分析。
- 未来心率样本与派生统计归属于对应训练记录；删除训练记录时应同时删除其本地心率样本和派生统计。
- 清除 saved device 只删除连接偏好，不自动删除既有训练历史；关闭心率功能也不自动删除过去记录。
- 不进行全天候、非训练场景或非活跃训练后台健康监测。
- TrainFlow 未来应支持用户主动导出自己的训练与心率数据。导出文件可由用户传输到电脑，用于个人分析、表格处理、研究或由用户主动导入外部模型进行数据分析。
- 导出必须由用户明确发起；导出只产生副本，不自动删除手机中的原始记录，也不代表 TrainFlow 自动把数据发送给任何 AI 或第三方服务。
- 导出前应说明心率与训练记录属于敏感个人数据；文件离开 TrainFlow 后，其保存、分享和第三方处理由用户控制。删除 TrainFlow 本地记录不能删除已导出的外部副本。
- 导出格式、字段、脱敏选项、文件保护和兼容方式必须由后续独立数据导出 Story 决定；E17-2 不提前锁定 CSV、JSON 或其他格式。

## 13. 非医疗边界

TrainFlow 不提供心脏疾病判断、危险心率诊断、医疗级告警、自动训练中断、康复或恢复时间处方、基于心率的精确热量修正，或“本次训练有益 / 有害健康”等确定性结论。

## 14. E16 遗产分类

### Adopt

- 胶囊视觉与互动：`adopted / frozen / direct reuse`。
- 设置页显式 opt-in、用户动作触发权限、用户主动有限时扫描。
- saved device 是便利提示而不是在线事实；用户点击后进行有限时精确匹配。
- 未训练只显示不记录、本地处理和非医疗表达。
- 单次训练复盘中的平均 / 最高心率、曲线、区间时长与覆盖率信息层级。

### Reject

- App 启动时自动扫描或连接。
- 把名称或地址当作永久身份。
- 非训练状态全天后台连接或监测。
- 手动心率输入、页面内联旧心率卡片和旧平均心率占位。
- 医疗告警、强制暂停和自动训练调整。
- 自动继承 E16 runtime 状态、计时阈值、D-078 或失败 controller。

### Defer

- 心率持久化、数据模型、采样率与 Room schema。
- 图表、统计、分析算法、跨训练趋势和复盘页面实现。
- 复盘页面的独立视觉审查与最终布局。
- 前台及活跃训练后台自动恢复的具体产品细化与实现。
- 用户数据导出格式、保护、字段和兼容合同。
- 具体 freshness 阈值和技术错误分类。
