# TrainFlow UI Skin Review 与用户测试前验收清单

**状态:** E8.4 审查清单
**适用范围:** Official Flow、Tile Flow、Big Type 三套内置 UI 皮肤，以及后续社区主题、布局和 shell 贡献。
**使用时机:** UI skin 变更合并前、E9 用户测试前、社区主题或布局 PR Review 前。

本文档只定义审查和验收标准，不引入第四套皮肤，不支持运行时插件市场、远程皮肤下载、第三方皮肤安装或动态代码加载。

## 1. 审查结论格式

每次 UI skin review 应记录：

| 项目 | 结果 |
|---|---|
| 皮肤或贡献名称 | Official Flow / Tile Flow / Big Type / 社区主题名 |
| 目标用户 | 例如默认用户、偏磁贴信息块用户、远距离大字用户 |
| 影响页面 | 首页、设置、计时执行、力量执行、确认层等 |
| 720x1280 检查 | Pass / Issue / Not applicable |
| 核心训练语义 | 未改变 / 有风险 |
| 权限与健康边界 | 保留 / 有风险 |
| 用户测试前结论 | Ready / Ready with E9 issue / Blocked |

若发现新的视觉阻塞问题，优先记录为 E9 用户测试或验收 issue；除非是 checklist、文案或测试保护层的小问题，不在 E8.4 大范围重做 UI。

## 2. 三套内置皮肤检查

### Official Flow

- 符合 `DESIGN.md` 的官方默认方向：清晰、克制、可信，浅色工作区 + 深色训练执行面板。
- 当前动作、主倒计时或组目标、主按钮的视觉层级高于历史、说明、未来健康数据和装饰。
- 卡片、按钮、chip、输入、训练执行面板优先使用 design token，不引入脱离设计系统的临时颜色。
- 信息密集页面保持可读，不把训练首页做成营销落地页。

### Tile Flow

- 保持磁贴语言：入口、计划指标、设置分组可以更模块化，但不得把训练执行页拆成大量零碎磁贴。
- 训练首页的计时默认入口仍清楚，力量训练和跟练入口同层可达。
- 计划列表/详情中的动作数、轮次、时长、休息和提醒等指标可扫读。
- 训练执行页只做轻度视觉适配，不能牺牲当前动作、倒计时/组目标和主控制效率。

### Big Type

- 保持大字可读：当前动作、主时间、本组目标和主按钮明显放大。
- 小屏不得因为字号放大把主控制挤出首屏。
- 信息密集页面可以继续沿用 Official/Tile 组合，不要求全站大字化。
- 固定底部控制区要保留必要控制，不用大段说明占据运动中的主区域。

## 3. 训练执行页固定主控制要求

任何内置皮肤或社区 layout 都必须满足：

### 计时训练

- 720x1280 小屏首屏内可见当前动作或休息状态。
- 主倒计时即时可见。
- 暂停/继续可达。
- 跳过可达。
- `+15秒` 可达，至少在休息或可延长休息的状态中可达。
- 结束训练可达，且不会被隐藏在不可发现的二级菜单里。
- 当前不显示心率卡片；未来健康数据不得高于当前动作、倒计时、下一步和主控制。

### 力量训练

- 720x1280 小屏首屏内可见当前动作。
- 准备态 `开始本组` 可达。
- 进行态 `完成本组` 可达。
- 确认态实际重量/次数与确认动作可达，并保留计划值预填语义。
- 暂停/继续可达。
- 结束训练可达。
- 当前不显示心率卡片；未来健康数据不得高于当前动作、本组目标、组耗时/休息倒计时和主按钮。

### 跟练雏形

- 复用计时流程和动作内容，不展示完整课程平台、真实视频库、自动语音教练或 AI 纠错假入口。
- 当前动作、媒体占位、倒计时、短提示、下一动作和控制按钮保持清楚。

## 4. 720x1280 小屏检查

每次关键 UI skin 变更至少检查 720x1280 竖屏：

- 首页：计时默认入口、力量训练入口、跟练入口、动作库/计划/设置入口不互相遮挡。
- 设置页：UI 皮肤选择、训练反馈设置、通知边界说明可读。
- 计时执行页：当前动作、倒计时、暂停/继续、跳过、`+15秒`、结束训练即时可见。
- 力量执行页：当前动作、本组目标、开始/完成/确认、暂停/继续、结束训练即时可见。
- 力量确认层：实际重量、实际次数、感受选择和确认按钮不溢出；计划值预填不被删除。
- 文案不得被按钮、底部导航、安全区或固定控制区遮挡。

## 5. 权限与非医疗化边界

UI skin 和社区贡献不得隐藏或弱化以下说明：

- 通知权限说明不能被隐藏。Android 13+ 通知权限关闭时，要说明训练仍可正常使用，提醒暂不会弹出。
- 计划提醒和活跃训练通知都必须表达为普通通知，不写成闹铃级强提醒、全屏强打断或后台精确计时承诺。
- 当前不显示心率能力；未来健康数据不得写成医疗告警、危险判断、疾病监测或训练中断依据。
- 恢复建议不得写成康复治疗、医疗诊断、疾病适应性建议或治疗承诺。
- 未接入真实心率设备时，不请求健康、身体传感器、蓝牙或定位权限。

## 6. 用户测试回看事项

E9 用户测试应专门回看：

- 热身、正式动作、动作后休息、轮间休息、放松/拉伸是否都应支持最后 N 秒提醒。
- 当前已明确覆盖动作与休息临近结束提醒；若热身、放松或其他计时阶段缺少最后 N 秒声音、震动或屏幕强化，应记录为 E9 回归或后续修复项。
- 训练提示音不得降低、暂停或打断其他 App 音乐/视频，不主动执行 audio ducking。
- 不同 Android 版本或设备上的音频共存异常应记录为后续平台音频适配问题。

## 7. 社区 UI 定制要求

社区可以改：

- theme token：颜色、字体、字号、圆角、间距和动效节奏。
- shell：首页布局、导航结构、dashboard 信息排序。
- 布局：页面入口组合、主按钮位置、训练执行页信息排布。
- 组件外观：按钮、卡片、chip、输入、训练状态块、指标条。

社区不可改：

- `WorkoutCommand` 语义。
- `WorkoutEvent` 语义。
- `WorkoutPlan` / `WorkoutSession` 数据契约。
- 计时或力量训练执行引擎。
- 力量单组完成后的实际记录确认和计划值预填语义。
- 通知、权限、心率和恢复建议的边界说明。

社区贡献必须附带：

- 目标用户说明。
- token 映射或变更说明。
- 训练执行页表现说明。
- 720x1280 小屏自检结果。
- 通知、心率、恢复建议和未实现能力边界自检结果。

## 8. 禁止范围

MVP 阶段不支持：

- 第四套内置皮肤。
- 运行时插件市场。
- 远程下载皮肤。
- App 内安装第三方 UI 包。
- 动态代码加载。
- 通过 UI skin 暗示或启动自动语音教练、AI 实时动作纠错、完整课程平台、真实心率设备或医疗告警。

开源 UI 定制的当前路径是 fork、编译期选择主题或 shell、提交社区主题或 layout PR。

## 9. E9 用户测试前 Ready Gate

进入 E9 用户测试前，应满足：

- 三套内置皮肤都在 registry 中，Official Flow 是默认皮肤。
- 未知或非法 skin id 回退到 Official Flow，不能直接进入 UI。
- 三套皮肤的 mode pill 对比度达到 WCAG AA。
- 三套皮肤 metadata 不为空，且说明目标用户和能力边界。
- 720x1280 小屏检查没有阻塞问题；非阻塞问题已记录为 E9 issue。
- 核心训练命令、事件、计划、会话、心率状态和恢复建议语义未被 UI skin 修改。
- 通知权限、普通通知、心率非医疗化和恢复建议非医疗化说明仍可见。
